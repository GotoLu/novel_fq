# Chapter Writer - 单章写作标准化流程

## 功能定义

单章写作标准化流程技能，负责从大纲核查到正文创作的完整链路管理。

**核心职责**：确保每一章的写作都经过"大纲核查→事件大纲→章节大纲→正文创作"的标准化流程，保证内容结构完整、逻辑连贯、风格统一。

---

## 项目文件结构

```
novel-project/
├── 大纲.md                          # 总大纲（100章完整设计）
├── 第二卷详细细纲.md                  # 卷级细纲（含各章场景划分）
├── 第X章详细大纲.md                   # 章节级详细大纲（含场景对话细节）
├── 02-人物设计.md                     # 人物设定
├── 正文/
│   ├── 第XXX章_标题_初稿.md           # 初稿
│   ├── 第XXX章_标题_修改稿.md         # 修改稿
│   └── 第XXX章_标题_终稿.md           # 终稿
```

```
│  步骤四：调用 content-writer 创作正文                        │
│  ├─ 4.1 传入章节详细大纲数据                                  │
│  ├─ 4.2 执行 content-writer 的标准三稿流程                   │
│  │   ├─ 初稿 → basic质量检查                                 │
```

## 步骤一：大纲核查

### 执行方式

使用文件读取和搜索工具，按以下优先级核查大纲完整性：

| 优先级 | 检查对象 | 文件路径模式 | 内容完整度 |
|--------|---------|-------------|-----------|
| 1 | 章节级详细大纲 | `novel-project/第X章详细大纲.md` | 最高（含场景对话细节） |
| 2 | 卷级细纲 | `novel-project/第X卷详细细纲.md` | 中等（含场景划分和核心对话） |
| 3 | 总大纲 | `novel-project/大纲.md` | 基础（含核心事件和章节表格） |

### 核查判定标准

| 核查结果 | 判定 | 后续路径 |
|---------|------|---------|
| 存在章节级详细大纲 | **完整** | 直接进入步骤三（基于已有大纲优化） |
| 仅有卷级细纲中的章节设计 | **部分完整** | 进入步骤二（补充事件大纲细节） |
| 仅有总大纲中的事件定义 | **基础** | 进入步骤二（从零编写事件大纲） |
| 无任何大纲 | **缺失** | 进入步骤二（从零编写事件大纲） |

### 核查输出格式

```markdown
## 大纲核查结果

| 项目 | 状态 | 文件位置 | 完整度 |
|------|------|---------|--------|
| 章节级详细大纲 | 存在/不存在 | 路径 | 高/中/低 |
| 卷级细纲章节设计 | 存在/不存在 | 路径 | 高/中/低 |
| 总大纲事件定义 | 存在/不存在 | 路径 | 高/中/低 |

**判定**：完整/部分完整/基础/缺失
**后续路径**：步骤X
```

## 步骤二：事件大纲编写

### 触发条件

当步骤一判定为"部分完整"、"基础"或"缺失"时执行。

### 编写原则

1. **忠实于总大纲**：事件大纲必须严格基于 `大纲.md` 中定义的核心事件，不得自行增删事件
2. **逻辑连贯**：事件之间必须有因果逻辑，不能跳跃
3. **伏笔衔接**：标注伏笔的埋设和回收，确保前后呼应
4. **人物一致**：人物行为必须符合 `02-人物设计.md` 中的设定

### 事件大纲格式

每个事件独立编写，格式如下：

```markdown
## 事件N：[事件名称]

### 事件基本信息
| 项目 | 内容 |
|------|------|
| **所属章节** | 第X章 |
| **事件类型** | 案件引入/调查/推理/抓捕/日常/转折 |
| **出场人物** | 人物A、人物B、... |
| **事件时长** | 故事内时间（如"约30分钟"） |
| **情绪曲线** | 起始情绪→终止情绪 |

### 事件核心内容
[用2-3句话概括事件的核心发生了什么]

### 事件详细展开
1. [具体情节步骤1]
2. [具体情节步骤2]
3. [具体情节步骤3]
...

### 关键对话
[列出本事件中必须出现的关键对话，含说话人和核心内容]

### 伏笔处理
| 伏笔ID | 类型 | 内容 | 说明 |
|--------|------|------|------|
| FXXX | 埋设/回收/延续 | 伏笔内容 | 衔接说明 |

### 与前后事件的衔接
- **承接前事件**：[如何从上一事件过渡]
- **引出后事件**：[如何为下一事件铺垫]
```

### 保存规则

- 事件大纲保存到 `novel-project/第X章详细大纲.md`
- 如果该章属于某个案件组（如第32-38章属于"消失的古董"案），也可合并保存到 `novel-project/第XX-XX章详细正文大纲.md`

## 步骤三：章节详细大纲编写

### 输入

- 步骤二产出的事件大纲（或步骤一确认的已有大纲）
- `02-人物设计.md` 中的人物设定
- 前文内容（前1-2章的终稿）

### 编写内容

章节详细大纲必须包含以下完整结构：


### 章节标题设计原则

1. **信息量**：标题应暗示本章核心事件，但不过度剧透
2. **吸引力**：使用悬念感词汇，激发读者好奇
3. **一致性**：与同卷其他章节标题风格统一
4. **长度**：2-6个字为佳，最长不超过8个字

### 保存规则

- 章节详细大纲保存到 `novel-project/第X章详细大纲.md`

## 步骤四：调用 content-writer 创作正文

### 调用方式

调用 `content-writer` 技能，传入以下参数：

```json
{
  "action": "write_chapter",
  "params": {
    "chapter_number": 32,
    "chapter_title": "凭空消失",
    "word_count_target": 3000,
    "content_type": "regular",
    "outline_data": {
      "core_event": "古董在公开展览中凭空消失，200人见证",
      "conflict": "真正的不可能犯罪：监控真实、门窗完好、200人见证",
      "characters": ["陆行舟", "秦墨寒", "周明远", "苏晚", "博物馆馆长"],
      "foreshadowing": ["F201-古董凭空消失", "F202-监控真实无造假"],
      "cliffhanger": "监控显示古董确实在众目睽睽下消失，没有任何人接近"
    },
    "pacing_type": "fast",
    "quality_check_level": "strict",
    "draft_stage": "v1"
  }
}
```

### content-writer 执行要求

1. **准备阶段**：获取章节详细大纲、人物设定、前文内容
2. **初稿**：撰写初稿，执行 basic 质量检查
3. **修改稿**：根据初稿问题修改，执行 standard 质量检查
4. **终稿**：根据修改稿问题修改，执行 strict 质量检查 + 节奏控制
5. **保存**：终稿保存到 `novel-project/正文/第XXX章_标题_终稿.md`

### 文件命名规范

| 阶段 | 文件名格式 | 示例 |
|------|-----------|------|
| 初稿 | `第XXX章_标题_初稿.md` | `第032章_凭空消失_初稿.md` |
| 修改稿 | `第XXX章_标题_修改稿.md` | `第032章_凭空消失_修改稿.md` |
| 终稿 | `第XXX章_标题_终稿.md` | `第032章_凭空消失_终稿.md` |

## 步骤五：同步更新（终稿完成后必须执行）

### 核心原则

**大纲是写作的起点，终稿是写作的终点。终点确定后，必须反向更新起点，保持各级大纲与正文一致。**

写作过程中不可避免地会出现：场景调整、对话改动、伏笔增减、人物行为微调等偏离大纲的情况。终稿完成后，必须将这些偏差同步回各级大纲，确保后续章节写作时参考的大纲是准确的。

### 同步更新流程

```
┌─────────────────────────────────────────────────────────────┐
│                    同步更新流程                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  5.1 终稿定稿确认                                           │
│      └─ 终稿已保存且通过strict质量检查                       │
│                                                             │
│  5.2 差异提取                                               │
│      ├─ 对比章节详细大纲 vs 终稿正文                         │
│      ├─ 识别所有偏差项                                      │
│      └─ 生成差异报告                                        │
│                                                             │
│  5.3 章节级大纲同步                                         │
│      ├─ 更新第X章详细大纲.md                                │
│      └─ 使其与终稿正文完全一致                               │
│                                                             │
│  5.4 卷级细纲同步                                           │
│      ├─ 更新第X卷详细细纲.md中对应章节的设计                 │
│      └─ 同步场景划分、核心对话、钩子、伏笔                   │
│                                                             │
│  5.5 总大纲同步                                             │
│      ├─ 更新大纲.md中对应章节的表格行                        │
│      └─ 同步标题、核心事件、伏笔编号                         │
│                                                             │
│  5.6 伏笔状态更新                                           │
│      ├─ 更新大纲.md中的伏笔追踪表                           │
│      └─ 标记已埋设/已回收/状态变更的伏笔                     │
│                                                             │
│  5.7 已写章节计数更新                                       │
│      └─ 更新大纲.md中的"已写章节"字段                       │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 5.2 差异提取

对比章节详细大纲与终稿正文，识别以下类型的偏差：

| 偏差类型 | 说明 | 示例 |
|---------|------|------|
| **场景调整** | 场景数量、顺序、字数分配与大纲不同 | 大纲4场景，正文3场景 |
| **对话改动** | 关键对话的内容或说话人与大纲不同 | 大纲中A说的话，正文改为B说 |
| **伏笔增减** | 正文中新增或删除了伏笔 | 大纲无F205，正文新增了F205 |
| **人物行为微调** | 人物的具体行为与大纲描述不同 | 大纲中陆行舟"沉默"，正文改为"自嘲" |
| **标题变更** | 最终标题与大纲标题不同 | 大纲"握手言战"，正文改为"竞争开始" |
| **钩子变更** | 结尾钩子与大纲设计不同 | 大纲设计悬念A，正文改为悬念B |
| **新增内容** | 正文中出现了大纲未设计的内容 | 大纲未设计某段环境描写，正文新增 |

**差异报告格式**：

```markdown
## 第X章 差异报告

### 偏差汇总
| 偏差类型 | 大纲版本 | 终稿版本 | 影响级别 |
|---------|---------|---------|---------|
| 场景调整 | 4场景 | 3场景 | 中 |
| 伏笔增减 | F201-F204 | F201-F205（新增F205） | 高 |
| 标题变更 | "握手言战" | "竞争开始" | 低 |

### 详细偏差列表
1. [偏差1描述]
2. [偏差2描述]
...

### 同步操作清单
- [ ] 更新章节详细大纲：[具体操作]
- [ ] 更新卷级细纲：[具体操作]
- [ ] 更新总大纲：[具体操作]
- [ ] 更新伏笔追踪：[具体操作]
```

### 5.3 章节级大纲同步

**更新规则**：
- 以终稿正文为准，更新 `第X章详细大纲.md`
- 更新内容包括：场景划分、对话设计、环境描写、人物心理、钩子、伏笔、幽默点
- 在文件末尾追加"同步记录"段落，记录更新时间和变更摘要

**同步记录格式**（追加在章节详细大纲末尾）：

```markdown
---

## 📋 同步记录

| 时间 | 操作 | 变更摘要 |
|------|------|---------|
| 2026-06-03 | 终稿同步 | 场景3新增陆行舟"找方向"领悟；伏笔新增F205；标题未变更 |
```

### 5.4 卷级细纲同步

**更新范围**：仅更新该章节对应的部分，不修改其他章节

**更新内容**：

| 更新项 | 说明 |
|--------|------|
| 章节标题 | 如有变更则更新 |
| 场景划分 | 与终稿实际场景保持一致 |
| 核心事件 | 与终稿实际核心事件保持一致 |
| 钩子设计 | 与终稿实际结尾钩子保持一致 |
| 伏笔列表 | 与终稿实际伏笔保持一致 |
| 人物出场 | 与终稿实际出场人物保持一致 |

**注意**：卷级细纲是概要级描述，不需要同步对话细节和环境描写，只需同步结构级信息。

### 5.5 总大纲同步

**更新范围**：仅更新该章节对应的表格行和相关伏笔

**更新内容**：

| 更新项 | 位置 | 说明 |
|--------|------|------|
| 章节标题 | 章节表格 | 如有变更则更新 |
| 核心事件 | 章节表格 | 与终稿一致 |
| 伏笔编号 | 章节表格 | 与终稿一致 |
| 已写章节 | 整体结构表 | 数字+1 |

**注意**：总大纲是概要级，只同步标题、核心事件、伏笔编号等关键字段，不同步场景细节。

### 5.6 伏笔状态更新

在 `大纲.md` 的伏笔追踪区域（如有）更新伏笔状态：

| 伏笔状态 | 含义 | 标记方式 |
|---------|------|---------|
| 已埋设 | 伏笔已在正文中出现 | 更新埋设章节号 |
| 已回收 | 伏笔已在正文中揭示 | 更新揭示章节号 |
| 状态变更 | 伏笔内容与原设计不同 | 记录变更内容 |

如 `大纲.md` 中没有伏笔追踪表，则在同步报告中记录伏笔状态变更，不自行创建新表。

### 5.7 已写章节计数更新

更新 `大纲.md` 整体结构表中的"已写章节"字段：

```
| **已写章节** | 第1-XX章 |  →  | **已写章节** | 第1-YY章 |
```

### 同步更新约束

1. **只增不改原则**：同步更新只能补充和修正现有大纲，不能删除其他章节的设计
2. **最小影响原则**：只更新与当前章节直接相关的内容，不连锁修改其他章节
3. **标记原则**：所有同步更新必须在差异报告中记录，便于回溯
4. **冲突处理**：如果终稿内容与总大纲核心设定冲突，以总大纲为准，在差异报告中标记冲突，由用户决定是否修改总大纲

### 同步失败处理

| 错误码 | 错误描述 | 处理方式 |
|--------|---------|---------|
| SYNC_TARGET_NOT_FOUND | 待同步的大纲文件不存在 | 跳过该级同步，在差异报告中记录 |
| SYNC_CONFLICT | 终稿内容与总大纲核心设定冲突 | 不自动修改总大纲，标记冲突由用户决定 |
| SYNC_PARTIAL_FAIL | 部分同步项失败 | 记录失败项，已完成项不回滚 |

## 关键规则

### 1. 大纲权威性

- `大纲.md` 是最高权威，事件大纲和章节大纲不得与总大纲矛盾
- 如发现总大纲存在逻辑问题，应记录问题但不得自行修改总大纲
- 卷级细纲是对总大纲的细化，与总大纲冲突时以总大纲为准
- **终稿完成后，正文成为事实标准，各级大纲应向正文对齐（核心设定除外）**

### 2. 前文一致性

- 写作前必须阅读前1-2章终稿，确保承接自然
- 人物状态、案件进度、伏笔状态必须与前文一致
- 不得引入与前文矛盾的设定

### 3. 质量底线

- 终稿必须通过 strict 级别质量检查（所有维度 ≥ 合格线）
- 字数偏差不超过目标字数的 ±15%
- 每章必须包含至少1个幽默点和1个悬念钩子

### 4. 流程不可跳过

- 步骤一（大纲核查）不可跳过
- 步骤二（事件大纲）仅在已有时可跳过
- 步骤三（章节详细大纲）不可跳过
- 步骤四（content-writer 三稿流程）不可跳过
- 步骤五（同步更新）不可跳过

## 容错与降级机制

### 核心原则

**不报错中断，而是降级处理**——当某个层级的定义缺失时，自动从下一层级或关联信息中补全，并明确标记补全来源，让用户知晓哪些内容是推断生成的。

### 分级降级策略

```
┌─────────────────────────────────────────────────────────────┐
│                    容错降级链路                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  章节级详细大纲（最完整）                                     │
│       ↓ 缺失                                                │
│  卷级细纲中的章节设计（中等完整）                              │
│       ↓ 缺失                                                │
│  总大纲中的章节表格+事件定义（基础）                           │
│       ↓ 缺失                                                │
│  上下文推断（最后手段）                                       │
│       ↓ 缺失                                                │
│  暂停并询问用户（不可自行编造）                               │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 缺失场景与处理方式

#### 场景A：总大纲中缺少该章节的事件定义

| 检查项 | 处理方式 |
|--------|---------|
| 总大纲中无该章节编号 | 从卷级细纲中提取核心事件作为替代 |
| 总大纲中有章节编号但无事件详情 | 从卷级细纲补充，标记 `[来源：卷级细纲]` |
| 总大纲和卷级细纲都无该章节 | **暂停流程**，向用户报告缺失情况，请求确认 |

**处理逻辑**：
1. 先检查卷级细纲是否有该章设计 → 有则降级使用，标记来源
2. 再检查总大纲中相邻章节的事件 → 推断该章可能承接/过渡的事件，标记 `[来源：上下文推断]`
3. 都无法推断 → **暂停并询问用户**，输出缺失报告

**缺失报告格式**：
```markdown
## ⚠️ 章节定义缺失报告

| 项目 | 状态 | 说明 |
|------|------|------|
| 章节编号 | 第X章 | 用户指定 |
| 总大纲定义 | ❌ 缺失 | 大纲.md中未找到该章节 |
| 卷级细纲定义 | ❌ 缺失 | 卷级细纲中未找到该章节 |
| 上下文推断 | ❌ 无法推断 | 相邻章节信息不足 |

**建议操作**：
1. 补充大纲.md中该章节的定义
2. 或提供该章节的核心事件描述，由skill生成事件大纲
3. 或指定参考的相邻章节编号

**流程状态**：已暂停，等待用户输入
```

#### 场景B：总大纲中有章节定义但缺少部分事件

| 缺失类型 | 处理方式 | 标记 |
|---------|---------|------|
| 缺少核心事件描述 | 从卷级细纲补充 | `[来源：卷级细纲]` |
| 缺少冲突点 | 从卷级细纲补充，或根据案件类型推断 | `[来源：推断]` |
| 缺少伏笔定义 | 从卷级细纲补充，或根据前后章伏笔链推断 | `[来源：推断]` |
| 缺少人物出场 | 从卷级细纲补充，或根据案件需要推断 | `[来源：推断]` |
| 缺少钩子设计 | 根据下一章事件反向设计 | `[来源：反向推断]` |
| 缺少幽默点 | 根据人物性格和场景类型设计 | `[来源：推断]` |

#### 场景C：卷级细纲与总大纲冲突

| 冲突类型 | 处理方式 |
|---------|---------|
| 核心事件冲突 | 以总大纲为准，记录冲突点 |
| 人物出场冲突 | 以总大纲为准，记录冲突点 |
| 场景划分不同 | 以总大纲核心事件为准，场景划分可参考卷级细纲 |
| 伏笔编号冲突 | 以总大纲为准，重新编号卷级细纲中的冲突伏笔 |

**冲突记录格式**：
```markdown
## ⚠️ 大纲冲突记录

| 项目 | 总大纲版本 | 卷级细纲版本 | 采用版本 | 原因 |
|------|-----------|-------------|---------|------|
| 核心事件 | [内容] | [内容] | 总大纲 | 总大纲为最高权威 |
| 伏笔FXXX | [内容] | [内容] | 总大纲 | 编号冲突，以总大纲为准 |
```

#### 场景D：前文终稿缺失

| 缺失类型 | 处理方式 |
|---------|---------|
| 前1章终稿缺失 | 警告用户，尝试从前2章或章节大纲中提取承接信息 |
| 前2章终稿都缺失 | **暂停流程**，建议先完成前文写作 |
| 前文存在但与大纲不一致 | 以前文终稿为准（已写内容优先），记录偏差 |

#### 场景E：人物设定文件缺失

| 缺失类型 | 处理方式 |
|---------|---------|
| 02-人物设计.md 整体缺失 | 从大纲.md和已写正文中提取人物信息，标记 `[来源：正文推断]` |
| 某个人物设定缺失 | 从已写正文中推断该人物性格，标记 `[来源：正文推断]` |
| 新人物（大纲中首次出场） | 根据事件需要设计基本人设，标记 `[来源：推断]` |

### 降级标记规则

所有通过降级/推断生成的内容必须标记来源，便于后续审核：

| 标记 | 含义 | 可信度 |
|------|------|--------|
| `[来源：卷级细纲]` | 从卷级细纲提取 | 高 |
| `[来源：上下文推断]` | 从相邻章节推断 | 中 |
| `[来源：反向推断]` | 从后续章节反向推断 | 中 |
| `[来源：推断]` | 根据案件类型/人物性格推断 | 低 |
| `[来源：正文推断]` | 从已写正文推断 | 中 |

### 不可自动处理的硬性缺失

以下情况**必须暂停并询问用户**，不可自行推断或编造：

1. **章节在总大纲和卷级细纲中均无定义**——无法确定写什么
2. **案件真相缺失**——不能自行编造案件真相
3. **关键伏笔的回收逻辑缺失**——不能自行决定伏笔如何回收
4. **人物重大转折缺失**——不能自行决定人物关系的质变

### 错误码汇总

| 错误码 | 错误描述 | 处理方式 |
|--------|---------|---------|
| CHAPTER_NOT_IN_OUTLINE | 总大纲和卷级细纲均无该章节 | **暂停**，输出缺失报告，询问用户 |
| EVENT_PARTIAL_MISSING | 总大纲有章节但缺少部分事件 | 降级补全，标记来源 |
| OUTLINE_CONFLICT | 卷级细纲与总大纲冲突 | 以总大纲为准，记录冲突 |
| CASE_TRUTH_MISSING | 案件真相未定义 | **暂停**，询问用户 |
| FORESHADOW_RECOVERY_MISSING | 关键伏笔回收逻辑缺失 | **暂停**，询问用户 |
| CHARACTER_TURN_MISSING | 人物重大转折未定义 | **暂停**，询问用户 |
| PREVIOUS_CHAPTER_MISSING | 前文终稿不存在 | 警告，尝试降级；前2章都缺则暂停 |
| CHARACTER_DATA_MISSING | 人物设定文件缺失 | 从正文推断，标记来源 |
| QUALITY_BELOW_STANDARD | 终稿质量不达标 | 返回修改，最多重试2次 |

## 使用示例

### 示例：写作第32章

**用户输入**："写第32章"

**执行流程**：

1. **步骤一：大纲核查**
   - 检查 `第32章详细大纲.md` → 不存在
   - 检查 `第二卷详细细纲.md` → 存在，包含第32章"凭空消失"设计
   - 检查 `大纲.md` → 存在，第32章属于"案件五：消失的古董"
   - **判定**：部分完整 → 进入步骤二

2. **步骤二：事件大纲编写**
   - 从大纲.md提取核心事件：古董在公开展览中凭空消失
   - 从第二卷详细细纲提取场景划分：4个场景
   - 为每个场景编写详细事件大纲
   - 保存到 `第32章详细大纲.md`

3. **步骤三：章节详细大纲编写**
   - 确定章节标题："凭空消失"
   - 设计4个场景的详细内容
   - 编写对话、环境、心理描写
   - 设计钩子、伏笔、幽默点
   - 保存到 `第32章详细大纲.md`（覆盖步骤二的文件，补充完整结构）

4. **步骤四：调用 content-writer**
   - 传入章节详细大纲数据
   - 执行初稿→修改稿→终稿流程
   - 保存终稿到 `正文/第032章_凭空消失_终稿.md`
