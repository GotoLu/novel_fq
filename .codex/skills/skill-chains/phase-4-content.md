# 阶段四：正文生产

本阶段目标是把设计落成读者愿意继续读的章节。正文不是扩写大纲，而是用场景、动作、冲突、情绪和节奏兑现前期承诺。

## 调用链

`plot-architect` 章节卡 → `character-designer` 人物状态 → `content-writer` → `quality-evaluator` → `problem-solver` 必要分诊 → `plagiarism-checker` → `progress-tracker`

## 技能分工

| 技能 | 职责 |
|------|------|
| `plot-architect` | 提供章节目标、阻碍、代价、变化、伏笔和接力点 |
| `character-designer` | 校准人物当前欲望、情绪、关系和行为边界 |
| `content-writer` | 写开篇、日常章、高潮段落和统一风格正文 |
| `quality-evaluator` | 验收 P0、P5、P6、P7、P8、P9、P15 |
| `problem-solver` | 对不追读、人物失真、场景无力和语言问题分诊 |
| `plagiarism-checker` | 检查正文、对话、场景和表达复用风险 |
| `progress-tracker` | 记录章节状态、问题、修订和下一章接力 |

## 问题沉淀：章节标题弱规范

已发现问题：章节标题容易退化为功能标签，例如“对抗”“误判”“翻盘”“低谷”。这类标题方便内部管理，但缺少读者点击欲、悬疑感和画面钩子，会削弱正文阶段的第一眼吸引力。

处理原则：

- 章节标题属于正文生产质量闸门，不只是文件命名。
- 标题必须服务读者点击和追读，同时准确承载本章核心事件。
- 标题不合格时，优先回退到 `plot-architect` 重拟章节卡标题，再由 `content-writer` 同步正文和文件名。
- 重要标题变更必须交给 `progress-tracker` 记录决策依据。

## 必须交付

- 章节卡。
- 章节标题吸引力检查结论。
- 人物当前状态。
- 章节正文。
- 章节质量报告。
- 必要改稿分诊记录。
- 原创性检查结论。
- 下一章接力点。
- 进度记录。

## 通过标准

- 第一屏有钩子，不慢热自辩。
- 章节标题有物件、动作、冲突、异常或悬念之一，不能只是剧情功能说明。
- 单章有目标、阻碍、代价和变化。
- 场景参与冲突，不只是背景。
- 情绪投注明确，读者知道为什么要在乎。
- 爽点有铺垫、有兑现、有回响。
- 章末留下下一章必须打开的理由。
- 风格稳定，句群有作者辨识度。

## 章节标题闸门

| 检查项 | 合格标准 | 不合格表现 |
|--------|----------|------------|
| 点击钩子 | 标题自带物件、动作、冲突、异常或悬念 | 只有“初见”“反击”“翻盘”“低谷”等功能词 |
| 信息控制 | 暗示核心事件，但不直接泄露真相或最终解法 | 标题直接写出凶手、真相或结局 |
| 画面感 | 读者能立刻想象一个具体场面、道具或压力 | 抽象概念堆叠，读者看完没有画面 |
| 类型感 | 悬疑、喜剧、爽点至少命中一种类型承诺 | 标题像工作日志或大纲小标题 |
| 系列一致性 | 同一案件组标题风格协调，有连续识别度 | 五章标题各说各话，没有统一气味 |
| 文件同步 | 正文 H1、文件名、章节卡、资产库和进度表一致 | 文件名、正文标题和章节卡互相打架 |

## 回退规则

| 问题 | 回退 |
|------|------|
| 标题平淡或像功能标签 | `plot-architect` 重拟章节标题，并记录标题优化依据 |
| 开头不抓人 | `content-writer` 重写开头钩子 |
| 单章没变化 | `plot-architect` 重做章节卡 |
| 人物不像自己 | `character-designer` 校准人物状态 |
| 场景无力 | `content-writer` 重写场景调度 |
| 文本相似 | `content-writer` 重构表达、场景组织和对话 |
