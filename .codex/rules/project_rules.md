# 项目全局规范

本文档定义了项目开发过程中必须遵循的核心原则和规范。

---

## 核心原则

### 1. 客观中立原则

**定义：** 基于事实和合理分析提供内容，避免主观臆断和过度迎合。

**具体要求：**
- 所有分析和建议必须基于事实依据
- 避免无根据的主观推测
- 不因用户偏好而扭曲客观事实
- 提供多角度分析，呈现完整图景
- 明确区分事实陈述和观点表达

**应用场景：**
- 案件逻辑分析
- 人物行为评估
- 情节合理性判断
- 质量评估报告
- 大纲逻辑检查

---

### 2. 最优决策原则

**定义：** 面对多种方案时，经多维度评估后直接提供最优解，并说明核心依据。

**具体要求：**
- 面对多方案时，必须进行多维度评估
- 直接提供最优方案，不列出所有选项让用户选择
- 必须说明选择该方案的核心依据
- 评估维度包括：可行性、效果、成本、风险等
- 最优方案必须经得起推敲和验证

**评估维度：**
1. **可行性：** 方案是否可执行
2. **效果：** 预期效果是否最优
3. **成本：** 时间、资源成本是否合理
4. **风险：** 潜在风险是否可控
5. **一致性：** 是否与现有设定一致
6. **扩展性：** 是否为后续发展留有空间

**决策流程：**
```
识别问题 → 生成方案 → 多维度评估 → 选择最优 → 说明依据 → 执行实施
```

**应用场景：**
- 大纲修改方案选择
- 章节标题优化
- 伏笔埋设位置确定
- 案件难度设定
- 人物成长轨迹设计

---

## 实施指南

### 在内容创作中的应用

#### 1. 案件设计
- **客观中立：** 案件逻辑必须合理，不能为了效果而牺牲逻辑
- **最优决策：** 选择最能体现人物特点的案件类型

#### 2. 人物塑造
- **客观中立：** 人物行为必须符合性格设定
- **最优决策：** 选择最能推动情节发展的人物行为

#### 3. 情节安排
- **客观中立：** 情节发展必须符合逻辑
- **最优决策：** 选择最能平衡节奏和效果的情节安排

---

### 在质量评估中的应用

#### 1. 逻辑检查
- 基于事实发现逻辑漏洞
- 不因个人偏好而忽视问题
- 提供客观的修复建议

#### 2. 质量评分
- 基于量化指标进行评估
- 避免主观臆断
- 提供可验证的评分依据

#### 3. 全局章节审查约束

所有章节卡、正文稿、章节评估和流水线输出，在判断“通过”前必须额外完成以下两项审查。两项审查属于章节级硬闸门，不得被结构完整、字数达标或内部评分替代。

##### 3.1 读者沉浸式体验审查

**定义：** 从普通读者的连续阅读体验出发，检查章节是否让读者自然进入场景、跟随人物感知、理解风险，并愿意继续翻页。

**必须检查：**
- 开头是否在读者尚未理解背景前，就用内部术语、生产语汇、摘要式复盘或作者说明阻断代入。
- 场景是否通过人物正在看见、听见、触碰、选择和承受的内容推进，而不是用说明文字替代现场。
- 信息解释是否被动作、对话、道具、冲突和情绪压力承载；禁止连续大段讲解让读者脱离人物处境。
- 章末钩子是否来自本章局面变化，而不是作者强行丢出的提示语或下一章预告。
- 读者是否能在不查看章节卡、资产库和评估报告的情况下，理解本章目标、风险、变化和追读问题。

**不通过表现：**
- 出现“本章”“下一章”“阶段任务”“本阶段定性”等生产过程语汇进入正文叙事或人物对白。
- 人物像在解释大纲，缺少即时反应、误解、迟疑、身体动作和环境压力。
- 章节读起来像案件报告、设定说明或评估摘要，而不是正在发生的故事。

##### 3.2 上帝视角语境审查

**定义：** 检查正文是否提前泄露角色当下不可能知道的信息，或让叙述、对白、判断带有作者/读者/后续剧情才拥有的全知语境。

**必须检查：**
- 角色判断是否只基于其当场可见证据、既有经历、权限范围和合理推理，不能引用后续章节真相。
- 叙述句是否提前替嫌疑人、幕后者、案件机制或人物动机定性；未被证实前必须保持“疑点、待证、可能、表层解释”等边界。
- 伏笔提示是否通过可观察异常呈现，不能用“真正的关键”“后来证明”“命运已经”等全知式标记替读者划重点。
- 章节评估和章节卡可以说明作者意图，但正文不得把作者意图转写成角色已经知道的结论。
- 多视角叙事必须明确当前视角知识边界，不能让一个角色拥有另一个角色或旁白才知道的信息。

**不通过表现：**
- 角色说出或想出只有作者、章节卡、后文真相才知道的因果关系。
- 旁白提前宣布“这就是凶手的漏洞”“真正的答案在某处”等未被剧情证实的结论。
- 伏笔不是埋设，而是用全知语气提前提示读者。

**记录要求：**
- 每份章节评估必须单列“读者沉浸式体验审查”和“上帝视角语境审查”结论。
- 若任一审查未通过，章节最多只能判定为“有条件通过”，并必须列出需修改的原句、问题类型和建议替换方向。
- 若正文出现生产语汇或明显上帝视角泄密，必须先修正文，再更新进度表；不得只在评估中备注。

## 示例

### 示例1：章节标题优化

**问题：** 第5章和第12章标题都是"歪打正着"

**方案评估：**
- 方案A：修改第5章 → 影响开篇设定，风险高
- 方案B：修改第12章 → 仅影响收束章节，风险低

**最优决策：** 修改第12章为"意外正确"
**核心依据：** 风险更低，且"意外正确"更符合第12章的核心事件

---

### 示例2：伏笔埋设位置

**问题：** F005伏笔埋设位置冲突

**方案评估：**
- 方案A：埋设在第40章 → 与第20章内容重复
- 方案B：埋设在第20章 → 符合人物成长轨迹

**最优决策：** 埋设在第20章
**核心依据：** 符合王小美的成长轨迹，避免内容重复

---

## 注意事项

1. **原则优先级：** 客观中立 > 最优决策
2. **验证机制：** 所有决策必须可验证
3. **文档记录：** 重要决策必须记录依据
4. **持续优化：** 根据实践反馈优化原则
5. **章节审查硬闸门：** 章节通过前必须完成读者沉浸式体验审查和上帝视角语境审查
